# Как устроен SupportFlow

Один Go-сервис принимает обращения, показывает интерфейс и запускает фоновые обработчики. PostgreSQL хранит и данные, и очередь — отдельный брокер для этого проекта не понадобился.

## Путь обращения

1. API проверяет сообщение и сохраняет его со статусом `pending`.
2. Обработчик забирает задачу через `FOR UPDATE SKIP LOCKED`, подбирает статьи и вызывает Алису AI.
3. Ответ проверяется по структуре и допустимым значениям, затем сохраняется вместе с токенами и снимками статей.
4. Оператор оценивает черновик, правит и подтверждает ответ, затем закрывает обращение. Правки ответа попадают в историю.

У задачи есть срок аренды и номер попытки. После сбоя её может забрать другой обработчик; запоздалый результат старой попытки не перезапишет новый. Сетевые ошибки, `408`, `429` и `5xx` повторяются в пределах лимита. Повторный вызов модели может быть платным, даже если предыдущий ответ потерялся по сети.

Черновик проверяется на известные служебные пометки, разметку, шаблоны и неподтверждённые обещания. При дефекте Алиса один раз пишет новый вариант в пределах общего таймаута. Сообщённые провайдером токены суммируются. Если проверка снова не пройдена, обращение получает ошибку `provider_reply_needs_editing` без автоматического повтора; плохой черновик не сохраняется. Нормализуются только края строк и пустые строки, содержимое ответа не вырезается. Проверка не заменяет оператора и может пропустить неизвестную формулировку.

## Код

```text
cmd/supportflow   запуск приложения
cmd/eval          проверка модели на примерах
internal/ticket   типы и валидация
internal/store    PostgreSQL, очередь и миграции
internal/llm      клиент модели и деморежим
internal/knowledge статьи и поиск по ним
internal/worker   фоновые обработчики

internal/config   настройки
```

## База знаний

Семь [Markdown-статей](../internal/knowledge/articles) встроены в приложение. Это учебные памятки оператору, без реальных тарифов и правил компании. Поиск сравнивает слова обращения с заголовками и ключевыми словами, приводит `ё` к `е` и использует первые пять букв длинных слов. Заголовок весит больше; в запрос попадают до трёх статей с оценкой не ниже половины лучшей. Это простой поиск, он может пропускать синонимы и подбирать лишние статьи.

В `analysis.sources` сохраняются именно переданные тексты, заголовки и SHA-256 версий файлов. Карточка открывает этот снимок, даже если базу позже изменили. Источники выбирает приложение: их наличие не означает, что модель верно применила сведения. В деморежиме источников нет.

Для новой статьи нужны заголовок `# ...`, пустая строка, `Ключевые слова: ...`, пустая строка и текст до 4 КиБ. После изменения файлов пересоберите приложение: `docker compose up -d --build app`.

## API

Тела запросов — JSON. Категории: `billing`, `access`, `technical`, `other`. Статусы: `pending`, `processing`, `completed`, `failed`.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/tickets` | Создаёт обращение из `title` и `message` |
| GET | `/api/v1/tickets` | Список: `q`, `view`, `category`, `status`, страницы `limit`, `offset` |
| GET | `/api/v1/tickets/{id}` | Обращение, анализ и последняя правка |
| PATCH | `/api/v1/tickets/{id}/review` | Сохраняет правку или подтверждение |
| PATCH | `/api/v1/tickets/{id}/closure` | Закрывает обращение или открывает снова |
| PUT | `/api/v1/tickets/{id}/feedback` | Сохраняет оценку исходного черновика |
| GET | `/api/v1/tickets/{id}/history` | История, от новых версий к старым |
| GET | `/api/v1/tickets/{id}/sources/{sourceID}` | Сохранённая статья как обычный текст |
| GET | `/api/v1/config` | Текущий провайдер без ключей |
| GET | `/healthz`, `/readyz` | Проверка процесса и соединения с БД |

При создании можно передать `Idempotency-Key`. Повтор с тем же ключом и сообщением вернёт исходное обращение; с другим содержимым — `409`. Без ключа каждый запрос создаёт новое обращение.

Пример правки после завершения анализа:

```json
{
  "category": "billing",
  "draft_reply": "Здравствуйте! Уточните дату и сумму списания.",
  "approved": true,
  "expected_revision": 0
}
```

В `expected_revision` передаётся текущий `review_revision` обращения. При конфликте версий API вернёт `409 review_conflict`, а текст останется в форме. `approved: false` сохраняет черновик без подтверждения. Повтор той же правки с текущей или непосредственно предыдущей ревизией не добавляет лишнюю запись.

Правка и её история сохраняются одной транзакцией. Исходный ответ модели хранится отдельно. Копировать кнопкой можно только подтверждённый ответ; после редактирования его нужно подтвердить заново.

`q` ищет буквальное вхождение в теме и сообщении без учёта регистра, до 200 символов. `view=open` показывает незакрытые, `closed` — закрытые, `needs_review` — завершённые разборы без подтверждённого ответа. Без `view` возвращаются все обращения. Фильтры работают вместе; поиск `%` и `_` не расширяется в SQL-шаблон.

Закрытие отделено от статуса разбора: `completed` не означает, что вопрос решён. Тело `/closure`: `{"closed":true,"expected_version":2}`. Нужен подтверждённый ответ; закрытый ответ нельзя править до открытия через `closed:false`. Оценка `/feedback`: `{"rating":"rewritten","reason":"Не учёл дату платежа","expected_version":2}`. Допустимы `useful` и `rewritten`; для второй оценки причина обязательна, до 1000 символов. Оценка относится к исходному черновику и доступна после закрытия.

Для этих действий берётся `version` из последнего ответа API. Несовпадение даёт `409 ticket_version_conflict`, а закрытие без подтверждения — `409 approval_required`. Повтор идентичного действия с непосредственно предыдущей версией не меняет данные. Блокировка строки не допускает одновременное закрытие и запись неподтверждённой правки. Последняя оценка хранится отдельно, история правок ответа от неё не меняется.

Для истории используйте `limit` до 50 и `next_before_revision` из ответа как следующий `before_revision`. Значение `0` в ответе означает конец. Для списка обращений `limit` — до 100, `offset` — до 10000. Тема ограничена 200 символами, сообщение — 16 КиБ, ответ оператора — 12 КиБ.

## Настройки и данные

Все переменные — в [.env.example](../.env.example). По умолчанию работают два обработчика, таймаут модели — 30 секунд, максимум три попытки и 100 обращений в очереди. В деморежиме внешних запросов нет.

Алиса подключается через Yandex AI Studio: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и модель `aliceai-llm-flash`. Нужен ID каталога, а не его название или ID облака. Ошибка `Unknown folder` означает, что этот каталог не найден. После изменения `.env` пересоздайте приложение.

Версии схемы учитываются в `schema_migrations` и применяются при старте. При обновлении старой базы текущая правка переносится в историю с пометкой `imported`. Правки, которые старая версия не хранила, восстановить нельзя. Новые изменения схемы добавляются отдельными миграциями.

Запуск и проверки описаны в [README](../README.md). `go run` сам не читает `.env`, а `docker compose down` сохраняет данные. Проект рассчитан на одного локального оператора, без учётных записей и отправки писем.
