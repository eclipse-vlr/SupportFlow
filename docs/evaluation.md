# Проверка Алисы AI

22 октября 2026 года. Провайдер — Yandex AI Studio, модель — `aliceai-llm-flash`. Использовался Responses API с JSON Schema и локальной проверкой результата. На каждый пример делалась одна попытка, без повторов. Лимит ответа — 1 500 токенов, таймаут — 30 секунд; параметры случайности не задавались.

## Категории

Основной набор — [32 синтетических обращения](../testdata/eval.json), по восемь на категорию. Разметка уже была в репозитории до прогона.

| Категория | Верно | Всего |
|---|---:|---:|
| Оплата | 8 | 8 |
| Доступ | 8 | 8 |
| Технические проблемы | 8 | 8 |
| Остальное | 8 | 8 |
| **Всего** | **32** | **32** |

Ошибок API и структуры ответа не было. Расход по данным API: 9 015 входных и 2 840 выходных токенов, всего 11 855. Это не расчёт стоимости из биллинга.

Медиана времени одного вызова — 7,11 с, 95-й процентиль — 15,92 с, максимум — 18,47 с. Вызовы выполнялись последовательно. Измерялся вызов клиента модели, включая чтение и проверку ответа; время очереди и интерфейса сюда не входит. Для процентиля использован метод ближайшего ранга: 31-е значение из 32 отсортированных длительностей.

Сырые результаты с исходными сообщениями, анализом и токенами: [JSON основного прогона](eval-alice-2026-10-22.json). Инструкция и код этого прогона сохранены в коммите `776fcb4`.

## Черновики

Все 32 черновика были просмотрены отдельно от счётчика категорий. В них нет запросов паролей, полных реквизитов карты или кодов подтверждения. При этом часть ответов содержит неподтверждённые обещания действий команды:

- Для приглашения в команду: «Мы проверим ситуацию и найдём решение».
- Для предложения тёмной темы: «Мы передадим его команде разработки» и обещание сообщить о внедрении функций.
- Для добавления языка: обещание передать вопрос специалистам и сообщить новости.
- Для обратной связи: «Мы учтём его при планировании обновлений».

Ещё одна особенность — повторяющиеся уточнения о названии продукта и фразы о необходимости проверки. У модели нет базы знаний продукта, поэтому такие ответы часто слишком общие. Удачная категория не означает, что черновик готов к отправке.

После основного прогона в инструкцию добавлен явный запрет обещать будущие действия команды и планы компании. Повторно проверены [четыре обращения](../testdata/eval-replies.json): двойное списание, приглашение, предложение тёмной темы и вопрос о языке.

Результат: 4 верные категории из 4, ошибок API нет. Расход — 1 349 входных и 315 выходных токенов. В ответе о списании модель предложила уточнить дату, сумму и идентификатор услуги без обещания возврата. В ответе о приглашении категоричное «найдём решение» сменилось на «постараемся помочь».

Проблема обещаний полностью не решена: для тёмной темы осталось «Мы учтём его при дальнейшей работе над сервисом», для языка — «Мы проверим эту информацию и сообщим вам». Одной инструкции недостаточно, чтобы гарантировать выполнение такого правила.

Сырые результаты: [JSON повторной проверки](eval-alice-replies-2026-10-22.json). Полный набор из 32 обращений после этой правки инструкции повторно не запускался. Отчёты сохранены отдельно, без замены исходных ответов исправленными.

## Как повторить

В `.env` должны быть `LLM_PROVIDER=yandex`, ключ и ID каталога. Из корня проекта:

```powershell
docker compose --profile tools run --rm --no-deps --env-from-file .env check go run ./cmd/eval -limit 0 -report eval-new.json
```

Только четыре проблемных примера:

```powershell
docker compose --profile tools run --rm --no-deps --env-from-file .env check go run ./cmd/eval -dataset testdata/eval-replies.json -limit 0 -report eval-replies-new.json
```

Обе команды вызывают платный API. Для нового запуска нужен новый путь отчёта: существующие файлы не перезаписываются. Отчёт содержит исходные сообщения и ответы, поэтому опубликованные примеры здесь только синтетические. ID каталога из URI модели в файлы не включается.

## Что показывает проверка

Подключение работает, структура ответа соблюдается, на этом наборе категории определены верно. Набор небольшой и простой; отдельного скрытого набора, сложных неоднозначных обращений и проверки инструкций внутри пользовательского текста в этом прогоне нет. Приоритеты не имеют отдельной эталонной разметки и не входят в процент точности.

Черновики остаются подсказкой оператору. Следующее полезное улучшение — история правок: она позволит сохранять ответ модели и сравнивать его с подтверждённым текстом. Для дальнейшей оценки нужны новые примеры и отдельные критерии качества ответов.
