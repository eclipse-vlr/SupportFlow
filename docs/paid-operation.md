# Платные вызовы и данные

Платный режим требует четыре явных целых значения в переменных окружения:
`AI_DAILY_LIMIT_NANOUNITS`, `AI_TICKET_LIMIT_NANOUNITS`,
`AI_INPUT_RATE_NANOUNITS`, `AI_OUTPUT_RATE_NANOUNITS`.
Одна денежная единица равна 10⁹ наночастей; цены задаются за один токен.
Используйте одну валюту во всех процессах одной БД. Значения из примеров
тестов — синтетические, переносить их в платную конфигурацию нельзя.

Перед каждой отправкой резервируется `(байты JSON + 4096) × входная цена +
max_output_tokens × выходная цена`. Резерв общий для API workers и CLI оценки,
включая переписывания. Обращение сохраняет свой предел при новых попытках.
При отказе бюджета worker завершает обращение с `ai_budget_exhausted`;
после исправления политики создайте новое обращение с новым ключом операции.

`ai_calls` хранит локальный ID, ID ответа провайдера, модель, версию инструкции,
состояние, время, цены, резерв и полученные токены. Полезный ответ без usage
сохраняется; интерфейс сообщает «Расход неизвестен». При аварии остаётся
`pending`, при сетевой ошибке или неполной статистике — `unknown`. Эти резервы
учитываются и после полуночи UTC. Старые обращения до миграции помечены
неизвестными: прошлые расходы нельзя восстановить из нулевых счётчиков.

Дневной предел считает известные затраты текущего дня UTC и все неразрешённые
резервы. Это оценка по настроенным ценам, не гарантия размера счёта провайдера.
Неожиданный расход выше резерва блокирует дальнейшие запросы до сверки.
Установите также доступные ограничения у провайдера и сверяйте Billing.

В `ai_budget_policy` первая конфигурация закрепляет цены; последующие процессы
могут только уменьшить лимиты. Для изменения цен или увеличения лимитов
остановите все платные процессы, сохраните копию БД, сверьте незавершённые
вызовы и измените строку политики в одной транзакции. Не обнуляйте `ai_calls`:
это снимет удержания и потеряет историю. Сверенные `unknown/pending` записи
изменяются только по подтверждённым данным провайдера; фиксируйте основание
сверки вне текстов обращений.

`GET /metrics` показывает очередь, её возраст, повторы, переписывания,
неизвестные вызовы, длительность провайдера и число оценок «переписан».
Метрики не содержат текстов, ключей, ID обращений и request IDs в labels.

Приложение остаётся локальным учебным инструментом. До работы с реальными
обращениями определите владельца данных, согласованный срок хранения, список
допустимых полей, процедуру удаления из БД и резервных копий. Пароли, ключи,
полные платёжные данные и коды подтверждения не отправляются модели.
Не считайте фильтры черновика универсальным маскированием персональных данных.
Обезличивайте обращения до загрузки; для сетевого доступа нужна авторизация.
Черновик всегда проверяет и подтверждает оператор.
