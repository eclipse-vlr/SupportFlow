# SupportFlow

Сервис на Go для обработки обращений в поддержку с Алисой AI. Модель определяет категорию и приоритет, кратко описывает проблему и предлагает черновик ответа. Оператор проверяет результат, вносит правки и подтверждает ответ.

Сделал для практики Go и работы с LLM API. Хотел пройти весь путь от приёма обращения до проверки ответа: очередь, запрос к модели, сохранение результата и обработка сбоев.

![Рабочая страница SupportFlow](docs/supportflow-preview.png)

## Что можно попробовать

- Создать обращение и дождаться разбора.
- Посмотреть краткое описание проблемы и причину выбранного приоритета.
- Изменить категорию и текст ответа.
- Сохранить черновик или подтвердить ответ.
- Отфильтровать список по категории и статусу.

Ответ остаётся в приложении. Отправка клиенту пока не реализована.

## Запуск

Понадобится Docker Desktop с Linux containers.

```powershell
git clone https://github.com/eclipse-vlr/SupportFlow.git
cd SupportFlow
Copy-Item .env.example .env
```

В `.env` включите Алису AI и заполните ключ и ID каталога:

```dotenv
LLM_PROVIDER=yandex
YANDEX_API_KEY=секретный_API_ключ_Яндекса
YANDEX_FOLDER_ID=идентификатор_каталога
YANDEX_MODEL=aliceai-llm-flash
YANDEX_BASE_URL=https://ai.api.cloud.yandex.net/v1
```

Ключ можно создать в [Yandex AI Studio](https://aistudio.yandex.cloud/) по [официальной инструкции](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key). Нужен секретный API-ключ, а в `YANDEX_FOLDER_ID` — ID каталога Yandex Cloud. Название каталога и ID облака не подойдут. Для запросов должен быть настроен доступ к API и биллинг.

Запустите приложение:

```powershell
docker compose up --build -d
```

Откройте [localhost:8080](http://localhost:8080) и создайте обращение, например:

> **Нет доступа после оплаты**
>
> Оплатил подписку, деньги списались, но доступ не появился.

Чтобы сначала посмотреть интерфейс без ключа, оставьте `LLM_PROVIDER=demo`. В этом режиме используются правила по ключевым словам, внешних запросов нет. Если меняли `.env` после запуска, примените настройки командой `docker compose up -d --force-recreate app`.

Используется [Responses API Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/create-prompt) и модель Alice AI LLM Flash. Полный URI модели собирается из ID каталога: `gpt://<каталог>/aliceai-llm-flash`. От модели ожидается JSON с категорией, приоритетом, объяснением и ответом. Структура и значения дополнительно проверяются в Go. Есть отдельная обработка отказов, обрезанных ответов и ошибок провайдера.

Ключ не попадает в браузер. `.env` исключён из Git и контекста Docker-сборки. В режиме LLM текст обращения передаётся провайдеру — для знакомства с проектом лучше использовать вымышленные сообщения.

## Проверка Алисы AI

На 32 учебных обращениях `aliceai-llm-flash` выбрала **32 верные категории из 32**. Ошибок API не было, расход — 9 015 входных и 2 840 выходных токенов. Это результат одного прогона на небольшом синтетическом наборе, а не оценка качества на реальных клиентах.

При просмотре черновиков нашлись лишние обещания от имени команды. Инструкция была уточнена, затем отдельно проверены четыре обращения: категории остались верными, но обещания в некоторых ответах сохранились. Полный набор после последней правки инструкции повторно не запускался. Черновики по-прежнему требуют проверки оператором.

Измерения, примеры ответов и оба JSON-отчёта: [результаты оценки](docs/evaluation.md).

## Что внутри

**Go 1.26+, PostgreSQL 17, pgx, обычные HTML/CSS/JavaScript.** Интерфейс только в тёмной теме, без фронтенд-фреймворка.

```text
cmd/supportflow   запуск приложения
cmd/eval          проверка классификации на примерах
internal/ticket   модель обращения и валидация
internal/store    PostgreSQL и очередь
internal/llm      API-клиент и деморежим
internal/worker   фоновые обработчики
internal/httpapi  HTTP API и интерфейс
internal/config   настройки из окружения
```

Очередь хранится в PostgreSQL. Для такого объёма отдельный брокер показался лишним: запись обращения и постановка в очередь происходят в одной транзакции.

Обработчики забирают задачи через `FOR UPDATE SKIP LOCKED`. У каждой попытки есть срок аренды и номер. Если процесс остановился, задачу можно подобрать после истечения аренды; результат старой попытки уже не перезапишет новую.

HTTP-запрос на создание не ждёт модель. При повторе запроса с тем же `Idempotency-Key` возвращается исходное обращение. Таймауты, число попыток, параллельность и размер очереди настраиваются через окружение.

Подробнее: [устройство проекта, API и настройки](docs/development.md).

## Проверки

```powershell
docker compose --profile tools run --rm check
```

Здесь форматирование, `go vet`, тесты с `-race`, интеграционные тесты с PostgreSQL и проверка зависимостей. Есть тесты на конкурентный захват задач, повторное создание обращения, просроченную аренду, отмену запроса к провайдеру и сохранение правок оператора.

В `testdata/eval.json` лежат 32 учебных обращения с ожидаемой категорией. Для проверки настоящей модели нужно задать переменные `LLM_PROVIDER=yandex`, `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в окружении терминала:

```powershell
go run ./cmd/eval -limit 5 -report eval-new.json
```

`go run` сам не загружает `.env`. Команда делает платные запросы к API; качество ответов нужно оценивать отдельно от точности категории. Полная проверка в Docker использует демоправила — её результат не является оценкой LLM.

Если Go не установлен, тот же запуск с настройками из `.env`:

```powershell
docker compose --profile tools run --rm --no-deps --env-from-file .env check go run ./cmd/eval -limit 5 -report eval-new.json
```

JSON-отчёт сохраняет исходные примеры, черновики, ошибки, время запросов и токены. Файл создаётся до первого запроса к модели; существующий отчёт не перезаписывается. Для полного набора используется `-limit 0`.

## Что пока не сделано

Авторизация, история правок и отправка ответа клиенту. Сейчас это локальное рабочее место одного оператора; Docker публикует порты только на loopback.

Ещё нет гарантии ровно одного вызова модели: при сетевом сбое запрос мог выполниться у провайдера, даже если приложение не получило результат. В базе учитываются известные токены, а не окончательная сумма из биллинга.

Остановить приложение с сохранением данных:

```powershell
docker compose down
```
