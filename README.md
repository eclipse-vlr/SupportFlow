# SupportFlow

Небольшой сервис для обработки обращений в поддержку. Принимает сообщение клиента, определяет категорию и приоритет, предлагает черновик ответа. Оператор может всё поправить и подтвердить.

Проект для практики Go и интеграции LLM API: кроме самого запроса к модели здесь есть очередь, сохранение результата, повторные попытки и обработка ошибок.

![Рабочая страница SupportFlow](docs/supportflow-preview.png)

## Что можно попробовать

- Создать обращение и дождаться разбора.
- Посмотреть краткое описание проблемы и причину выбранного приоритета.
- Изменить категорию и текст ответа.
- Сохранить черновик или подтвердить ответ.
- Отфильтровать список по категории и статусу.

Ответ остаётся в приложении. Отправка клиенту пока не реализована.

## Запуск

Понадобится Docker Desktop с Linux containers.

```powershell
git clone https://github.com/eclipse-vlr/SupportFlow.git
cd SupportFlow
docker compose up --build -d
```

Приложение: [localhost:8080](http://localhost:8080).

Первый запуск работает **в деморежиме**. Он разбирает сообщения по ключевым словам, не вызывает внешнюю модель и не требует API-ключа. Это удобно для проверки интерфейса и очереди.

Пример обращения:

> **Нет доступа после оплаты**
>
> Оплатил подписку, деньги списались, но доступ не появился.

## Подключить LLM

```powershell
Copy-Item .env.example .env
```

В `.env` нужно указать:

```dotenv
LLM_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini-2025-04-14
```

Затем пересоздать приложение и добавить новое обращение:

```powershell
docker compose up -d --force-recreate app
```

Используется Responses API со Structured Outputs. От модели приходит JSON с категорией, приоритетом, объяснением и ответом. Результат дополнительно проверяется в Go. Есть отдельная обработка отказов, обрезанных ответов и ошибок провайдера.

Ключ не попадает в браузер. `.env` исключён из Git и контекста Docker-сборки. В режиме LLM текст обращения передаётся провайдеру — для знакомства с проектом лучше использовать вымышленные сообщения.

## Что внутри

**Go 1.26+, PostgreSQL 17, pgx, обычные HTML/CSS/JavaScript.** Интерфейс только в тёмной теме, без фронтенд-фреймворка.

```text
cmd/supportflow   запуск приложения
cmd/eval          проверка классификации на примерах
internal/ticket   модель обращения и валидация
internal/store    PostgreSQL и очередь
internal/llm      API-клиент и деморежим
internal/worker   фоновые обработчики
internal/httpapi  HTTP API и интерфейс
internal/config   настройки из окружения
```

Очередь хранится в PostgreSQL. Для такого объёма отдельный брокер показался лишним: запись обращения и постановка в очередь происходят в одной транзакции.

Обработчики забирают задачи через `FOR UPDATE SKIP LOCKED`. У каждой попытки есть срок аренды и номер. Если процесс остановился, задачу можно подобрать после истечения аренды; результат старой попытки уже не перезапишет новую.

HTTP-запрос на создание не ждёт модель. При повторе запроса с тем же `Idempotency-Key` возвращается исходное обращение. Таймауты, число попыток, параллельность и размер очереди настраиваются через окружение.

Подробнее: [устройство проекта, API и настройки](docs/development.md).

## Проверки

```powershell
docker compose --profile tools run --rm check
```

Здесь форматирование, `go vet`, тесты с `-race`, интеграционные тесты с PostgreSQL и проверка зависимостей. Есть тесты на конкурентный захват задач, повторное создание обращения, просроченную аренду, отмену запроса к провайдеру и сохранение правок оператора.

В `testdata/eval.json` лежат 32 учебных обращения с ожидаемой категорией. Для проверки настоящей модели нужно задать переменные `LLM_PROVIDER=openai` и `OPENAI_API_KEY` в окружении терминала:

```powershell
go run ./cmd/eval -limit 5
```

`go run` сам не загружает `.env`. Команда делает платные запросы к API; качество ответов нужно оценивать отдельно от точности категории. Полная проверка в Docker использует демоправила — её результат не является оценкой LLM.

## Что пока не сделано

Авторизация, история правок и отправка ответа клиенту. Сейчас это локальное рабочее место одного оператора; Docker публикует порты только на loopback.

Ещё нет гарантии ровно одного вызова модели: при сетевом сбое запрос мог выполниться у провайдера, даже если приложение не получило результат. В базе учитываются известные токены, а не окончательная сумма из биллинга.

Остановить приложение с сохранением данных:

```powershell
docker compose down
```
